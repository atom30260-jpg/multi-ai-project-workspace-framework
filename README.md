# Multi-AI Project Workspace & Knowledge Base Framework

中文名：多 AI 项目工作台与知识库隔离框架

一个本地优先的多 AI 项目管理框架，用于组织项目工作台、Obsidian 知识库、项目记忆、AI 工具适配、任务交接与断网恢复。

## 它解决什么问题

当同一个项目需要由 Codex、Claude、Gemini、Grok 或其他 AI 工具协作时，容易出现：

- 项目文件、对话记录和记忆互相混用
- 不同 AI 的配置、规则和上下文互相污染
- 更换 AI、断网或新机后无法继续推进
- 项目资料堆积，无法判断该存到哪里
- AI 修改了不属于自己的工具目录或项目资料

本框架通过“全局控制层 + 独立项目单元 + 项目知识库 + AI 私有适配区”的分层方式处理这些问题。

## 核心原则

1. 每个项目独立拥有本地工作台、必要/非必要文件夹、Obsidian 知识库、项目记忆和治理规则。
2. 每个 AI 工具只维护自己的全局配置和私有适配记忆，默认不得修改其他 AI 工具目录。
3. 项目共享的是经过规范记录的本地资料、任务状态、交接文档和项目知识库，不是彼此的私有配置。
4. 重要事件，例如架构调整、Git 推送、部署、任务闭环和正式记忆更新，应按影响范围回写项目知识库。
5. 新机或断网恢复时，先恢复通用框架，再由使用者选择需要恢复的具体项目。
6. 普通对话不全量扫描知识库；只在重要治理事件中按需核验相关材料。

  -> 全局门禁、通用偏好、工具配置与恢复材料

  -> 非必要/
