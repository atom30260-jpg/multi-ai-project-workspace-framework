# 纯框架新机恢复指南

## 这套模式恢复什么

只恢复通用管理框架：

- 文件必要/非必要分层。
- 多项目登记和项目进门顺序。
- 每个项目的主线、需求规划台和治理规则台。
- 项目记忆候选池与全局升级门禁。
- 多 AI 适配区和权限规则。
- 重要事件的影响范围回写流程。
- 新项目建立、交接和审计模板。

## 这套模式不恢复什么

- 任何旧项目名称、旧项目文件和业务资料。
- 旧对话和历史任务。
- 旧项目的 Git、分支、自动化和运行状态。
- 任何账号、Token、Cookie、密码、私钥或证书真实值。
- 任何本体运行资产或项目专属配置原件。

## 一条命令

把本模板文件夹放到新机后执行：

```bash
zsh "<模板包路径>/bootstrap-framework-only.sh" "<新机框架根目录>"
```

例如：

```bash
zsh "<模板包路径>/bootstrap-framework-only.sh" "$HOME/AI-工作框架"
```

脚本创建每个 AI 独立本体模板、项目本地工作台模板、项目 Obsidian 实用目录、AI 适配区、项目登记、跨 AI 交接和恢复记录。它不读取旧数据，也不连接任何旧项目。

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File "<模板包路径>\bootstrap-framework-only.ps1" -Destination "$HOME\AI-工作框架"
```

## 一条命令完成后的引导

1. 读取 `00-全局控制层/全局门禁.md`。
2. 复制一份 `05-项目模板`，改成新项目 ID。
3. 为新项目填写身份卡，绑定本地工作台和项目 Obsidian 路径。
4. 在项目 Obsidian 内建立公共知识区和各 AI 独立适配区。
5. 只把新项目产生的资料写入新项目位置。

## 如果不使用脚本

也可以让 Codex 逐步引导：

```text
请使用“纯框架新机恢复模式”。
只创建多项目文件分层、项目登记、主线/需求规划台/治理规则台、记忆门禁、AI 适配区和回写模板。
不要读取、恢复或引用任何旧项目、旧数据、旧对话或本体资产。
完成后给我框架恢复回执，并等待我登记第一个新项目。
```

## 成功标准

```text
框架可用 = 目录骨架存在
          + 每个 AI 本体模板存在
          + 全局门禁可读
          + 项目登记表为空但可填写
          + 本地工作台和项目 Obsidian 模板同时存在
          + AI 适配区位于项目 Obsidian
          + 跨 AI 交接模板可用
          + 没有旧项目数据混入
```
